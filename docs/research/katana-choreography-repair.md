## Recommendation, with limits

Evaluate the **released native ComfyUI EditVid sampler**, unchanged, as a separately named optional research profile. It is a better mechanism to investigate than another edge-guided parameter sweep: it reconstructs from every source frame and retains source features and inversion trajectories across editing. This is a candidate for the failing choreography, not proof it fixes it. Keep existing LTX recipes and failures intact.

The upstream [EditVid paper](https://arxiv.org/html/2609.04190v1) reports an occlusion ablation (MF-S 66.27 versus 64.90 without global injection), and explicitly warns that severe occlusion can weaken correspondence. Its reported speed of 3.15 seconds/frame is on H200 and **is not an estimate for this native wrapper or our clip**. No inspected source establishes success on these two fighters.

- Official algorithm: [PLAN-Lab/EditVid](https://github.com/PLAN-Lab/EditVid/tree/ba40bed5b4bf63acb913e6be1fdc462df695e99e), Apache-2.0 at this commit. Relevant files: `editvid/pipeline.py` (source RF inversion and trajectory anchoring), `editvid/transformer.py` (temporal attention/correspondence), `run_editvid.py` (persistent chunk caches). The paper mentions a prospective MIT release; the actual pinned repository LICENSE is Apache-2.0.
- Existing native implementation: [CanFromEarth/ComfyUI_FLUX-Klein-EditVid](https://github.com/CanFromEarth/ComfyUI_FLUX-Klein-EditVid/tree/a58b02dd71e0a7d1f9e04276aeedeb9e1220bfcc), Apache-2.0, released September 12. Exact complete graph: [`examples/editvid_native.json`](https://github.com/CanFromEarth/ComfyUI_FLUX-Klein-EditVid/blob/a58b02dd71e0a7d1f9e04276aeedeb9e1220bfcc/examples/editvid_native.json).
- `nodes.py`: `EditVidSampler`, native model validation, source/reference conditioning, inversion and edit passes.
- `core.py`: midpoint RF inversion, Euler editing, tiled cycle-filtered correspondence and soft latent anchor.
- `temporal.py`: adjacent-frame KV memory retained across chunks, global anchor feature transfer in the first 12 blocks.

This is an **independent native adaptation**, not an official PLAN-Lab Comfy release. Its tiled correspondence search, collision resolution and deterministic token selection differ from the official implementation; no numerical parity claim is made. Reuse it with attribution rather than silently calling a new implementation canonical EditVid.

### Actual graph and core compatibility

The released graph has 13 nodes: UNETLoader + CLIPLoader + VAELoader; two plain CLIPTextEncode nodes (source description and requested edit); LoadVideo → GetVideoComponents → ImageScale → VAEEncode; Flux2Scheduler → EditVidSampler → VAEDecode → SaveWEBM. All source frames are encoded individually. Each receives its own original-frame reference latent. The sampler inverts those latents, uses source trajectories during editing, and carries temporal state across chunks. It does not duplicate, interpolate or loop output frames. It does not accept external appearance/first-frame references or painted masks.

Inspection of our pinned Comfy core `79cf64c21a1dba50749945ba9fe2e3a692f45438` confirms the required attention input/output hooks, `img_slice`, block replacement and Flux2Scheduler source interfaces. The subsequent isolated run imported the actual node, accepted the graph and reached the saver after sampling/decoding. It has not been integrated into the public application. It requires ordinary Torch/Comfy, not the separate Diffusers environment needed by the official Python runner.

The node explicitly rejects wrong model architecture, regional/CFG batching, noise masks and incompatible patches. It has no automatic smaller-chunk retry. Four inference steps require two model calls per inversion step and one per editing step: twelve model evaluations per chunk, not four total.

## Model compatibility and licensing

**Do not substitute Apache Klein 4B, our FLUX3 models, a Base checkpoint, a KV checkpoint, or a quantized loader.** The native guard requires hidden size 4096, eight dual blocks, global modulation, no guidance embedding and 128-channel source latents. Official Klein4B has hidden size 3072 and five dual blocks. FLUX3 uses a different native model/text-encoder path. The official EditVid release documents Klein9B; its published cross-backbone experiment is FLUX.1-Kontext, not 4B/FLUX3. Bypassing the guard would be a new port with changed feature selection, not supported reuse.

The code is Apache-2.0; the **9B weights are under the FLUX Non-Commercial License**. See the [model card](https://huggingface.co/black-forest-labs/FLUX.2-klein-9B) and [exact pinned model license, v2.1](https://huggingface.co/black-forest-labs/FLUX.2-klein-9B/blob/92196c8e11f7b6cf2b7493e037d8c5345c559216/LICENSE.md). Its terms distinguish non-production testing/evaluation from production/end-user model use. Do not advertise commercially unrestricted model inference, a commercial hosted service, or Comfy Cloud availability based on the Apache code license. Any commercial permission is a separate BFL matter. Preserve both algorithm/port credit and model terms; do not redistribute weights in the application bundle.

## Commercial-use fallback follow-up

The strongest **existing native workflow** found in this follow-up is [ComfyUI-RAVE at 92d19be](https://github.com/spacepxl/ComfyUI-RAVE/tree/92d19be86cdcec198088757c07873919d3c8e1b1), MIT. Its complete 14-node `workflow/RAVE_basic_workflow.json` uses SD1.5, source inversion through `BNK_Unsampler`, depth ControlNet and `KSamplerRAVE`. The sampler shuffles source latents and their matching control images into grids on each denoising step, then restores frame order. It is an independent native implementation of [the MIT RAVE research code](https://github.com/RehgLab/RAVE/tree/c836b194549dc0cdc8dfedea056ebfab5bd9d8c6), not a proven solution for our fighters.

This is a materially different licensing option from Klein9B: the inspected [SD1.5 checkpoint repository](https://huggingface.co/stable-diffusion-v1-5/stable-diffusion-v1-5/tree/451f4fe16113bff5a5d2269ed5ad43b0592e9a14) and [original depth ControlNet](https://huggingface.co/lllyasviel/ControlNet/tree/e78a8c4a5052a238198043ee5c0cb44e22abb9f7) are ungated and declare OpenRAIL licenses, which retain use restrictions rather than a blanket non-commercial-only condition. The example also needs [ComfyUI_Noise at 0c9ec19](https://github.com/BlenderNeko/ComfyUI_Noise/tree/0c9ec19b16dc72334cb8ce82c3774aed183048e4), GPL-3.0, and the depth/video helper packages. Separate external installation and their notices would be required; this is not an all-MIT model/runtime package.

Outstanding compatibility matters prevent calling this a ready replacement: the old native example uses a 3×3 grid, 25 inversion/sampling steps, a particular converted depth checkpoint filename and a fixed 12fps sink. The node pads a non-square-multiple frame batch by repeating its last latent and trims back to the original batch length at return; a 49-frame application must retain that behavior and replace the fixed sink with the actual source frame rate/audio. Its SD1.5 example is not evidence that a 3072×1728 image-equivalent grid of nine 1024×576 frames will fit or preserve the occlusion. Current Comfy API compatibility, exact helper/model pins, memory, and all-frame quality remain unverified. Do not silently replace the approved EditVid comparison or download these dependencies.
