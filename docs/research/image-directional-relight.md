## Lighting map and reproducibility

`imageLightingMap.ts` renders an opaque1024² PNG as an explicit conditioning artifact. Gradient/color interpolation derives from Apache-2.0 [ComfyUI-IC-Light `utils/image.py`](https://github.com/kijai/ComfyUI-IC-Light/blob/22811d903af8a90100dccef1c4b579526649a6ab/utils/image.py); OpenFrame extends the gradient projection to the existing azimuth/elevation controls and uses a centered gradient at front/rear. Softness controls map falloff, brightness controls luminance, color controls RGB. These are map-authoring semantics, not a physical light transport simulator.

The prompt declares the nearest trained horizontal direction (45° bins), Above at≥60° elevation, Below at≤−60°. The continuous controls also affect the rendered map, so the label and actual map are both visible. The saved document records all scalars and `openframe-qwen-lightmap-v1`; the PNG is uploaded explicitly, shown before generation, retained as `reference_asset_id`, protected as a document/job input, and exported alongside the source. `APP-CONTEXT.json` retains the controls; the actual PNG is conditioning authority. Changing controls requires Apply lighting map, preventing stale-map submission. Historical FLUX projects remain prompt-guided and preserve their explicit models/captions.

The released source scaling is `round(axis*sqrt(1024²/(W*H)))`; VAE encoding crops to an8-pixel grid. The API and UI report that actual output size; arbitrary aspect/resolution/batch controls are not exposed for this fixed recipe. This can crop a few edge pixels and regenerate detail. There is no original-pixel preservation claim.

Local ComfyUI uses native nodes and pinned downloadable components. Comfy Cloud is explicitly unavailable for this profile until its exact models/adapters are supported there. No Cloud run has been performed. The scoped dedicated-profile comparison below now establishes a directional result in the evaluated comparison.

## Source-preserving foreground finish: released-code audit

The corrected Qwen outputs do not merely add a removable object far from the subject. Native `LoadImage` followed by the same `FluxKontextImageScale` puts the original on the exact1024² conditioning canvas. At(x240,y75), the original dark hair is RGB[12,9,23], while hard/diffuse outputs are[248,252,254]/[246,251,254]. At(x260,y50), original[15,12,26] becomes[197,208,218]/[215,223,232]. The visible panel touches and replaces the upper-left hair boundary; face/neck/clothing are not covered by the panel's main area. These point samples plus visual inspection establish local overlap, **not** a full segmentation or pixel-accurate matte. `panel-edge-inspection.json` retains the native resize method and samples. The original background also changes from gray to blue-gray.

The most directly reusable released portrait-relight components are in Apache-2.0 [ComfyUI-IC-Light-Native,40883a839d2a719ad3d3a454700609b94b1a9c65](https://github.com/huchenlei/ComfyUI-IC-Light-Native/tree/40883a839d2a719ad3d3a454700609b94b1a9c65). Its [detail-transfer example](https://github.com/huchenlei/ComfyUI-IC-Light-Native/blob/40883a839d2a719ad3d3a454700609b94b1a9c65/examples/ic_light_detail_transfer.json) extracts foreground alpha with `easy imageRemBg`, separates RGB via `SplitImageWithAlpha`, and uses native `ImageCompositeMasked` atx0/y0 without resize. However, node46 composites the original foreground into decoded **latent guidance before sampling**, not onto the final output. Final node51 is Kijai's `DetailTransfer`, add mode/sigma1/blend1, without a connected mask. It adds original high-frequency detail to blurred generated RGB. This is useful detail preservation, **not** an already-released guarantee of untouched original background or silhouette.

That [Apache-2.0 DetailTransfer implementation](https://github.com/kijai/ComfyUI-IC-Light/blob/22811d903af8a90100dccef1c4b579526649a6ab/nodes.py) computes `(source - blur(source)) + blur(target)` in add mode. Its optional mask blends back toward the generated target, so simply enabling it would not restore the original background. It cannot recover original geometry from a displaced generated silhouette, and generated low-frequency panel spill can remain. The official [IC-Light background demo](https://github.com/lllyasviel/IC-Light/blob/bcf3f29ca85be8a4686215f477b546f5030be8b7/gradio_demo_bg.py#L327) similarly computes foreground matting for conditioning but returns generated RGB without an exact original-background composite. Its different SD1.5 model stack is not needed just to reuse alpha compositing.

A minimal **explicit adaptation**, without another diffusion run, can use the existing native BiRefNet foreground extraction (already-declared Comfy-Org model pin,444,473,596bytes,MIT) and native `ImageCompositeMasked` after the retained Qwen output: destination=original image on the same conditioning canvas, source=relit image, alpha=reviewed foreground matte. Native Comfy's compositor is the released multiply-and-add implementation in `comfy_extras/nodes_mask.py`; no new solver/plugin is required. This would keep pixels where alpha=0 exactly unchanged relative to the scaled original, while relighting the foreground. It must be labelled foreground-only relighting, not whole-scene relighting or source-native-resolution preservation. No mask has yet been generated for this portrait and no such composite has been accepted.

**Critical tradeoff:** original alpha alone retains the bright panel where it replaced old hair. Generated alpha alone can expose old hair behind a displaced silhouette and depends on excluding the panel correctly. Soft alpha can retain mixed white edge color. Intersecting separately reviewed original/generated support would leave original shading in their disagreement band; that would be a disclosed additional adaptation, not the cited workflow's guaranteed behavior. Foreground estimation/decontamination cannot reconstruct pixels classified as fully opaque but already replaced by the panel. Therefore no blind alpha finish or default promotion is justified. The bounded next evidence, if authorized, is actual original/generated portrait mattes and CPU native-compositor inspection on the retained images—not another prompt/sampler run or manually painted panel removal. All examined small source/workflow files are retained under the retained review record.
