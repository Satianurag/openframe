# Image model selection: current evidence

Research snapshot: **29 October 2026**. Scope: generation, image editing, reference identity, product fidelity, and background removal for OpenFrame's image/video/VFX screens. Retrieved through Context.dev from benchmark operators, model authors, and Comfy's documentation. This is source research, **not a new inference test or a claim that these models are already integrated**. No weights were downloaded and no tests were run for this audit.

## Decision

**FLUX.2 Klein 4B should remain a fast, permissively licensed baseline, not our advertised quality leader.** The current quality shortlist is FLUX 3 Image Klein, Qwen-Image-2.1, and Fibo 2.0. FLUX 3 Klein is the strongest immediate implementation candidate because it combines competitive independent rankings, official native ComfyUI support, references, and spatial controls. That recommendation is an engineering judgement, not a statistically proven win over the other two. Its conditional license and complete prompt-processing pipeline must be respected.

For strict product preservation, preserve original product pixels through matting/compositing when the requested transformation permits it; a reference-conditioned image generator does not guarantee unchanged branding. For cutouts, retain the existing BiRefNet path while considering its matting variants and the newer FeyNoBg challenger. Do not substitute generated RGBA imagery for faithful extraction without an explicit user choice.

### FLUX 3 implementation detail that changes the recommendation

The official pipeline expects a full scene caption. Its model card warns that short raw prompts give generic results. The reference CLI uses a separate **9B prompt upsampler** (18.8 GB weights); the author reports about **28 GB additional GPU memory** on an 80 GB GPU. It also requires its matching Qwen3-VL-4B encoder, autoencoder, and flow-map-compatible inference. Reusing FLUX.2's encoder/sampler is not a valid upgrade. The user-facing original prompt and expanded caption should both be recorded. [Official pipeline instructions](https://huggingface.co/black-forest-labs/flux-3-image-klein).

BFL's hosted API includes prompt expansion and pixel restoration. Exact preservation outside an edit is therefore not established merely by loading the open checkpoint or supplying a box. Local restoration needs explicit masking/compositing semantics and provenance. [BFL release, 15 Oct 2026](https://bfl.ai/blog/flux-3-image-klein).

For Soul/reference identity: expose references as guidance, not trained identity or guaranteed face locking. For Marketing: exact original-pixel product placement is a different operation from generative pose/material changes. A faithful copy/paste operation may preserve text perfectly while failing the requested scene interaction; both objectives matter.

## Background removal and alpha fidelity

| Candidate/evidence | Finding | Practical choice |
| --- | --- | --- |
| **BiRefNet general / HR-matting / dynamic** | Official MIT project has dedicated matting/2K variants and dynamic-resolution training. Standard 1024² FP16 inference is reported around **3.45–3.5 GB** on RTX4090; that is not a 4K HR-matting guarantee. Native Comfy integration exists. | Keep our proven base path, but choose the checkpoint by hard objects versus hair/transparency. Preserving output canvas dimensions does not mean the model inferred at that resolution. [Official repo/model zoo](https://github.com/ZhengPeng7/BiRefNet). |
| **FeyNoBg**, 27 Jul 2026 | Apache-2.0 weights; BiRefNet-derived mixed segmentation/matting training. Author reports best published S-measure on **4 of 8** benchmarks and within 2% on the other four. | New credible permissive challenger. S-measure is not complete alpha-edge/transparent-material proof; no matched native Comfy runtime or complete VRAM claim was established here. [Author report](https://huggingface.co/blog/feyninc/feynobg), [weights/license](https://huggingface.co/feyninc/FeyNobg). |
| **BEN2** | MIT public weights and CPU/CUDA implementation. Separate commercial model is also advertised. | Another legitimate specialist; no retrieved common benchmark establishes that its public weights beat the above on our tasks. Do not conflate commercial and open variants. [Official model card](https://huggingface.co/PramaLLC/BEN2). |
| **withoutBG Bench v0**, 26 Aug 2026 | 60 ground-truth alpha images, 14 systems, MAE/MGE and edge-band error. Reported MAE: withoutBG Open **0.0292**, BiRefNet General **0.0426**, U²-Net **0.1283**; lower is better. | Useful public per-image evidence, but vendor-operated and its own pipeline routes some inputs to BiRefNet. Not an independent universal winner or a comparison with FeyNoBg/BEN2. [Methodology/disclosure](https://withoutbg.com/benchmarks/open-background-removal), [scores](https://withoutbg.com/compare). |

Qwen2.1's generated alpha and Fibo's removal claims do not establish faithful source extraction. Likewise, a SAM segmentation mask is not automatically an accurate soft alpha matte for hair, glass, defocus, and motion blur. The appropriate pipeline should retain source RGB while estimating alpha, with optional documented foreground decontamination.

## Implementation priorities and later verification boundary

1. Add a distinct **FLUX3 Klein profile and its complete native workflow**, preserving existing Klein2 jobs. Separate original prompt, expanded caption, reference order, boxes/masks and preservation mode. Verify licensing eligibility without presenting conditional open weights as Apache software.
2. Make image references and limits model-driven: current backend `reference_asset_ids` is capped at four and image graphs lack mask/bounding-box controls. New models support up to ten, but backend validation, exports, assets, and UI must agree before exposing that claim.
3. Keep **Qwen2.1 and Fibo2** as explicit licensed/research alternatives; keep **QwenEdit2511/FireRed** as permissive editing candidates. Do not hide a proprietary API behind an open-weight model name or silently substitute it on failure.
4. Give product-preserving composition and generative product edits distinct controls. Retain a specialist alpha path; consider FeyNoBg/HR-matting only with compatible, pinned implementations.
5. After the user reopens validation: compare identical rights-cleared portrait/product/logo/reference sets, judge requested change and preservation separately, inspect alpha edges, and measure actual cold/warm runtime and peak memory. Record model revision, file hashes, quantization, encoder/VAE, prompt expansion, sampler/steps/guidance, seed, input order, resolution and restoration. No such new runs were performed for this report.

The current source still routes image generation/editing through `flux-klein-4b` and extraction through `birefnet`. The new candidates above are researched choices, not completed integration or quality-validation claims.
